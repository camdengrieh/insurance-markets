## 0. Bottom line

1. **A platform-level aggregator in the strict sense (one service that registers every prediction-market venue with fees, geography, API capabilities, trading reachability, resolution oracle, liquidity and cross-venue links, kept fresh and machine-readable) does not exist.** What exists is five partial things: (a) *volume/identity registries* (DefiLlama, Prediction Index, PM Wisdom), (b) *one small structured registry with a real schema* (Prediction Almanac), (c) *capability directories hidden inside unified-API products* (ccxt `exchanges.json` + `has` maps; Predictefy `GET /v1/exec/venues`, key-gated; Parsec `GET /api/v1/exchanges`, host now dead), (d) *single-purpose feeds* (PolyKal `fees.json` for Kalshi+Polymarket), and (e) *hand-curated awesome-lists* that go stale. (H, sections 2-3, 7)
2. **Closest, by dimension.** Registry data to join on: **DefiLlama** (133 "Prediction Market" rows plus 14 prediction "Interface" rows, keyless API, includes XO Market and Trueo). Registry *shape* to copy: **Prediction Almanac** (`platform.schema.json`, CC0 data, daily rebuild) plus **ccxt's `has` map** plus **Predictefy's `requirements{credentials,funding,geo}`**. Unified code covering the most venues: **ccxt** (now has 9 prediction exchanges, MIT, released 2026-10-14), **Synpath** (8 venues, trading + smart order routing for Kalshi and Polymarket, 3 weeks old), **Predictefy** (16 venues, the only one listing XO). Unified *trading layers*: **River Markets** (Kalshi, Polymarket, Polymarket US, Crypto.com, Novig; one River ID per exchange listing), **Kairos**, **Synpath**. (H)
3. **XO and Trueo are almost invisible to the aggregator layer.** XO appears only in Predictefy (vendor claim of an armed build/submit/cancel lane; "Nothing has ever been submitted to XO yet"), DefiLlama (volume adapter), and Prediction Index (directory). Trueo appears only in DefiLlama and Prediction Index (as "Truemarkets"); no aggregator, SDK or PayBox surface lists it. Limitless is well covered (ccxt, pmxt, dr-manhattan, Synpath, Predictefy, Predexon). (H, section 10)
4. **Nothing federates other aggregators.** The only aggregator-of-aggregators pattern found is **resale**: BlockRun sells Predexon v2 through x402 as a "100% pass-through" at a flat $0.0085 per call. There is no platform-directory API that is keyless, complete and capability-bearing. (H, section 7)
5. **The aggregator layer has a high mortality rate in 2026.** Dome (Polymarket acquired it, APIs ended 2026-04-28), Metaforecast (discontinued 2026-07-09), Fireplace (cross-venue terminal that had raised $1.5M in Feb 2026; trading halted 2026-08-15, M), Parsec (all four `parsecapi.com` hosts fail DNS today), Verso (`www.verso.trading` does not resolve), Converge (deployment disabled, L). Directories still list some of them as live (Prediction Index lists Dome as live; PM Wisdom marks "Dome API" Active). **Design consequence: own a thin registry with a freshness TTL; take only liveness/volume from third parties; never depend on one hosted aggregator at runtime.** (H/M, section 8)
6. **What remains for us** (gap): (i) XO and Trueo adapters/records; (ii) the registry fields nobody publishes together: fee parameters with their fetch endpoint, resolution/void policy, bot/wash-trading policy, PayBox reachability, depth-based liquidity tier, shared-liquidity/mirror links; (iii) a verified-date and TTL discipline; (iv) cross-venue *market* linking, which none of the platform-level products does (River explicitly does not link listings; see `docs/research/10` section 4 for the matching method). The proposed schema is section 9, with machine-checked seed records in `fixtures/linking/`.

## 4. Level 3: unified client libraries and SDKs ("ccxt for prediction markets")

### 4.1 ccxt itself now has prediction-market exchanges (new finding; doc 09/10 treated pmxt as "the" ccxt-for-prediction-markets)

- `github.com/ccxt/ccxt`: MIT, 44,449 stars, pushed 2026-10-18, npm `ccxt@4.5.88` published 2026-10-14. Directory `ts/src/prediction/` holds **`binance, hyperliquid, kalshi, limitless, myriad, opinion, polymarket, predictfun, sxbet`** (9 classes, 96-217 KB each); `exchanges.json` has a dedicated `"prediction"` list of those 9 ids (and an empty `predictionWs`). First commit touching the directory: 2026-07-15; latest 2026-10-14 (GitHub commits API, path-filtered, ≤20 commits). All are `certified: false`; `pro: true` (WebSocket) for polymarket, opinion, predictfun, myriad, sxbet. (H)
- **Capabilities read from each class's `has` map (H, my script on raw source):** `createOrder`, `cancelOrder`, `fetchMarkets`, `fetchEvents`, `fetchOrderBook`, `fetchTicker`, `fetchPositions` true on all nine (Limitless/Predict.fun `fetchBalance` false); `fetchTradingFee` true only for Polymarket and Myriad; `watchOrderBook` true for Polymarket, Opinion, Predict.fun, Myriad, SX Bet; Kalshi, Limitless, Hyperliquid, Binance have no WebSocket.
- **Data model (H, `ts/src/base/types.ts`)**: hierarchy Event -> Market -> Outcome; `PredictionMarket{ marketType: binary|categorical|scalar, executionModel: clob|amm|parimutuel, collateral, resolutionSource, resolved/resolvedOutcome, settlementValue, tickSize, limits, fees{trading, resolution}, openInterest }`, `PredictionEvent{ mutuallyExclusive, resolutionSource, tags, url }`, `PredictionOutcome{ price, bid, ask, settleFraction, negRisk }`, standalone `PredictionOrder/Position/Settlement/OpenInterest/TradingFee` addressed by an `outcome` handle `"MARKET:LABEL"` (no `symbol`). **Platform-level:** only `describe()` (`id, name, countries, rateLimit, urls{www, doc, fees, api}, has{}, certified, pro`). No fee formula, geo list, oracle or void policy per platform.
- No XO, Trueo, Probable, Gemini, Smarkets. **Cross-venue linking: none.**

## 12. Answer to the question

**Does a platform-level aggregator exist?** Not as one product. There are registries that list platforms (DefiLlama, Prediction Index, PM Wisdom, Prediction Almanac) and unified-API products that keep a private venue/capability list (ccxt, Predictefy, formerly Parsec), but none combines a public, machine-readable, regularly verified record of fees, geography, API capabilities, trading reachability, resolution oracle, liquidity and cross-venue links, and none federates the others (only resale, BlockRun over Predexon).

**Who is closest?** For data: **DefiLlama** (breadth, keyless, includes XO and Trueo, daily). For structure: **Prediction Almanac** (schema with `geo`, `data`, `routes_to`, `status`, `as_of`, `defillama` join key; CC0). For capability semantics: **Predictefy** (`requirements{credentials, funding, geo}` and `has`) and **ccxt** (`has`, `executionModel`, `collateral`). For execution breadth: **ccxt** (9 venues) and **Synpath** (8 venues with SOR for Kalshi+Polymarket); for institutional routing: **River Markets**.

**What gap remains for us?** (1) No aggregator or SDK covers Trueo, and only Predictefy (beta, closed, never submitted an XO order) covers XO; both need our own records and an XO adapter. (2) The fields that decide edge and safety (fee parameters and where to fetch them, void and oracle policy, bot policy, PayBox reachability, depth-based liquidity tier, mirror links) are published nowhere in one place. (3) Everything third-party is perishable (nine dead or dark items in 2026), so the registry needs `last_verified`/`ttl_days` and fail-closed reads. (4) Cross-venue market equivalence is still ours to do (doc 10 funnel); Synpath's `event_id`, Prediction Hunt's `group_id` and Oddpool's `basis_class` are inputs, not substitutes.
