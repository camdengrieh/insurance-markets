READ-ONLY: unauthenticated GETs of public pages, docs, static client JS (read as text, never executed), the keyless tool-catalog endpoint, DefiLlama public API, `gh api` file reads, and two read-only PayBox `discover_plugins` searches. Tags: **H** = read first-hand in a primary source this session (URL cited); **M** = secondary source, small-model page summary, or my own inference; **L** = weak or stale. "NOT FOUND (searched: ...)" means not documented where I looked.

## 0. Bottom line

1. **TrueNorth is not a prediction-market venue. It is an AI "agentic brokerage" / trading-intelligence product (operator ADVENT AI PTE. LTD., Singapore) that routes self-directed orders to other venues.** Its prediction-market feature is a **Polymarket odds data tool** (`polymarket_insight`). (H: homepage, docs readme, partner API doc.)
2. **The only HIP-4 link is a Hyperliquid builder code.** DefiLlama lists "TrueNorth Outcome" as an *Interface* on Hyperliquid L1 tagged "Hyperliquid HIP4 Builder" (H). That listing is **auto-generated by DefiLlama's generic Hyperliquid builder factory** for TrueNorth's existing builder address (H: `factory/hyperliquid.ts` line `"truenorth-outcome": { builder: "truenorth-perps", market: "outcome", start: "2026-08-29" }`), so its existence alone does not prove a shipped HIP-4 product.
3. **But the shipped client does contain a HIP-4 order path.** TrueNorth's public client JS classes any Hyperliquid order with asset id >= 1e8 as `"HIP4"` and attaches a per-market HIP4 builder fee (H, fixture `tn_client_bundle_hip4_builder_and_order_excerpt.txt`). So a TrueNorth user can plausibly place HIP-4 orders (M: UI exposure unconfirmed, login-gated).
4. **Volume through it is negligible.** DefiLlama: TrueNorth Outcome all-time volume **$796**, entirely on 2026-08-29 ($382) and 2026-08-30 ($414), **$0 every day since** (H, fixture). Builder fee is 0 (all-time fees $0, H).
5. **Liquidity is 100% shared with Hyperliquid HIP-4.** Every order lands on the HyperCore HIP-4 books. **Not an independent arbitrage leg.** Counting it would double count the Hyperliquid adapter. See the sibling notes `docs/research/venues/hyperliquid-hip-4-outcomes-native.md` (P1) and `outcome-xyz.md` (skip, same reasoning).
6. **No public trading or market-data API for outcomes.** TrueNorth's API (`https://tn-api.truenorth.xyz`) is an authenticated, read-only AI/market-data API (58 tools) with **no HIP-4 / outcome tool** (H, catalog fixture). No public order-placement API; trading happens inside its own client, which signs with a Hyperliquid API/agent key held client-side.
7. **adapter_priority = skip.** Duplicate liquidity, front end only, near-zero outcome flow, no outcome data in its API. Build the Hyperliquid HIP-4 adapter instead. Optional (very weak) signal: TrueNorth's `hyperliquid_smart_money` and Polymarket odds tools, not for outcomes.

## 2. Kind and market model

- **Kind:** `broker-or-frontend` (AI trading-intelligence terminal plus non-custodial order-routing interface plus optional "Agent Execution Services"). H: homepage ("The World's First Agentic Brokerage"), docs readme ("AI trading intelligence platform", "AI TradingView"), Terms s.5.7/5.8.
- Terms s.5.7(b): it does "not operate an exchange, matching engine, order book ... match, execute, clear, or settle any order" (H). Terms s.5.6(c)(4): "TrueNorth does not facilitate, broker, intermediate, or settle any prediction market positions or event contracts" (H). This **contradicts** the builder-code/HIP-4 order path in the client; treat the legal text as boilerplate that predates or ignores HIP-4 (M).
- **Market model = Hyperliquid HIP-4 when used for outcomes** (not TrueNorth's own): fully collateralised binary outcome tokens on a merged Yes/No CLOB on HyperCore; order asset id `100_000_000 + 10*outcome + side`; categorical via "questions"; scalar via fractional settlement (H on the sibling note's reading of the official HIP-4 page; client JS agrees with the `>= 1e8` asset-id rule, H). TrueNorth has no markets, tokens or books of its own.
- Venues TrueNorth lists on its homepage: Hyperliquid, Lighter, Binance, Bybit, Bitget, Variational (WebFetch summary, M); client config also has Ondo Perps and Lighter builder blocks (H, fixture).

## 3. Chains and collateral

- Execution chain for outcomes: **Hyperliquid HyperCore** (not an EVM chain). Collateral **USDC** per the sibling Hyperliquid note (M here). DefiLlama tags chain "Hyperliquid L1" (H).
- TrueNorth itself is off-chain software; "non-custodial", holds no keys (Terms s.5.7(b)(1), H as claim). Wallet connection via WalletConnect / injected wallet (Terms s.5.7(g), H).
- Client signs orders with an `ExchangeClient` built from a **Hyperliquid API-wallet private key held in the client** (code path errors with "Hyperliquid API private key is not connected" when absent; PIN-based decrypt helper) (H code excerpt, M interpretation: standard agent-wallet pattern, key stored locally and PIN-protected).

## 5. Trade path

- **No public order API.** Orders are built and signed inside TrueNorth's own client: a Hyperliquid `ExchangeClient` `order` action with `builder: {b: <builderAddress>, f: <tenths of bps>}`; asset id >= 1e8 selects the `HIP4` fee tier; mixed markets must be separate orders ("Mixed-market builder fees require separate orders") (H, fixture). Builder settings come from a **JWT-protected** `GET /user/builder-config` (H), which I did not call.
- Builder address (public, labelled "TrueNorth" on flowscan builders per DefiLlama comment, M): `0x30599f69164b854a2c10ada95e5cd219b72d5216` (H: from DefiLlama adapter source; it is TrueNorth's, not ours).
- TrueNorth's "Agent Execution Services" can submit orders autonomously within user-set permissions (Terms s.5.8, H). Pricing/permissions detail NOT FOUND.
- Older desktop docs say the opposite ("Can you execute trades for me? No. Analysis only", H quote); the homepage, Terms and client code supersede that (M).
- The correct programmatic route for our plugin is **Hyperliquid directly** (EIP-712 phantom-agent signed actions to `POST /exchange`, agent wallets, optional builder code). TrueNorth adds nothing a PayBox plugin could call.

## 6. Fees

- **Builder fee:** DefiLlama's adapter comment says TrueNorth "charges a 0% builder fee" (M, a code comment). Consistent: TrueNorth Outcome all-time fees = $0 (H). The client config carries per-market `fees_bps` for `perp` (max 10 bps), `spot` (max 100 bps) and `HIP4` (no schema cap besides the account's `max_fee_bps` approval ceiling); the live HIP4 value is server-side and **NOT FOUND** (needs JWT). Builder fee unit sent to Hyperliquid is tenths of a basis point (`f = round(10*bps)`) (H code).
- **Platform fees:** subscription tiers plus usage "Credits" (Terms s.10, H); pricing page not found; Stablejack says TrueNorth had not published pricing as of August 2026 (M). Terms s.5.7(h): compensation is "solely subscription fees and platform fees" plus disclosed builder-code arrangements (H).
- **Hyperliquid protocol fees for HIP-4:** the official HIP-4 page still says fees are zero (stale); sibling note estimates all-in 11-25 bps incl. builder fees, with outcome fees live since about 2026-08-15 (M, from the sibling note; not re-verified here). Builders earn on **sell orders** only (H per sibling).

## 7. Resolution mechanism and dispute risk

TrueNorth has none; it inherits Hyperliquid HIP-4 resolution (deployer-settled for the large majority of open markets, no trader dispute window per the sibling note's tracker count: 284 of 289 open, M). TrueNorth's own terms add a disclaimer: prediction-market positions "may be illiquid and subject to resolution disputes", and it "shall not be liable" for third-party operation or resolution (Terms s.5.2 / s.5.6(c), H). For an arbitrage scanner the risk is the Hyperliquid deployer's rules, not TrueNorth's.

## 8. Geo / ToS / automation

- **Operator:** ADVENT AI PTE. LTD., Singapore (UEN 202523238G) per docs readme (H); Terms s.6.6 separately calls Advent AI an exempted Cayman company (H, inconsistent; flag).

Do not scrape the web app; use the keyed API or go to Hyperliquid.

## 11. Adapter recommendation

- **adapter_priority: skip** (duplicate liquidity; front end; negligible outcome volume; API has no outcome data; no public trade path).
- Do instead: one `hyperliquid-hip4` adapter (WS `l2Book`/`bbo`, `outcomeMetaUpdates`) as in the sibling note. Treat builder codes (TrueNorth's, Outcome.xyz's and dozens of others) only as a fee parameter on the same book (`approveBuilderFee`, sell-side fee).
- Optional low-value signals: `hyperliquid_smart_money` (positions of large profitable Hyperliquid wallets; perps), `polymarket_insight`, `venue_costs` (fee/slippage/funding config). Would require a partner/API key and acceptance of Terms s.9; not worth it for the arbitrage scanner.
- Watch item: re-check `truenorth-outcome` daily volume in DefiLlama in a month. If it becomes non-zero, it only means more flow into the same books.
